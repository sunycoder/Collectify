# 跨平台代码排查

本轮检查窗口创建/恢复、原生全屏、资料卡、桌面组件、WebContentsView、插件前后台、退出清理、启动设置读取和主界面渲染。代码审查与 Windows 回归不能证明所有 macOS 原生交互都没有问题。

## 已处理

| 风险                                               | 调整与验证                                                                  |
| -------------------------------------------------- | --------------------------------------------------------------------------- |
| 重复布局导致原生视图重绘、资料卡闪动               | 同状态不重复设置尺寸/可见性；全屏切换时收起资料卡；增加显示中的资料卡回归   |
| 切到别的插件后，旧资料卡异步加载完成又弹出         | 显示前同时核对当前插件可见性、首页/遮罩状态和资料所属条目                   |
| 关闭窗口或停用插件时，旧加载回调继续操作已销毁对象 | 检查窗口、视图和后台记录身份；辅助窗口加载期间被关闭时不再设置透明度        |
| 并发打开桌面待办导致空白窗口或旧模式覆盖新模式     | 共享加载 Promise，使用请求序号，仅最后一次请求允许展示；隐藏/销毁撤销旧请求 |
| 显示器变化或工作区较小时辅助窗口跑出屏幕           | 资料卡和桌面待办按目标显示器工作区约束位置与尺寸，包含负坐标测试            |
| 程序尚未初始化，Dock/第二实例激活导致重复创建      | 初始化阶段只记录唤起请求，准备完成后再恢复主窗口                            |
| 退出不等待异步业务，或一个插件清理失败跳过后续清理 | before-quit 延迟退出，禁止新增业务并等待已有任务，逐个执行清理并汇总异常    |
| 并发启用插件或启动 MCP 造成重复定时器/监听         | 对同一插件激活、同一 MCP 启动合并 Promise，停止等待启动完成                 |
| 主界面数据刷新导致已打开的插件更多菜单消失         | 插件管理行按实际元信息变化更新，无关业务状态变化不重建菜单                  |

## 性能调整

- 未使用 AI 时不加载整份 MCP SDK，日历库只在进入日历视图时加载。
- 初始插件与宿主页面并行，后台与前台并行，保留初始化错误处理。
- 默认插件清单按 discover 周期缓存；原生外部插件签名校验仍保留。
- 设置按需要的键一次读 SQLite，避免同一刷新反复打开数据库；不使用可能过期的跨实例设置缓存。
- 同一轮事件合并宿主状态发布；插件列表无变化时不重建 DOM。

可用 `npm run smoke -- --startup-metrics` 观察就绪时间。隔离数据、冷暖缓存、系统负载差异会影响样本，不能把最快一次作为承诺。

## 明确的边界与未覆盖项

- macOS 需要在真实系统执行全屏进入/退出、Dock/菜单栏恢复、辅助功能授权及实际外部应用粘贴验证；对应自动流程已加入完整冒烟，本轮未远程运行新的 Mac 代码。
- Linux 主动粘贴仍提示手动粘贴，Windows 的 Everything 引擎不适用于 Mac/Linux。
- 本地搜索的压缩包目录预览仍依赖打包的 Windows 7z.exe/7z.dll，Mac/Linux 没有等价实现；读取失败时回退为文件元信息。这是已识别的平台功能缺口，不能当作“全部系统功能相同”。原生插件需独立适配、重新签名后发布。
- 系统通知、密钥环、系统代理/证书、不同显示器缩放、睡眠唤醒仍需要对应系统和真实环境测试。

继续优化应以真实数据量和插件数量做剖析。下一层可考虑延迟初始化未使用后台、对大列表分页/虚拟化；这些涉及数据导入、提醒和后台采集契约，不能仅为启动时间跳过必要功能或签名检查。
