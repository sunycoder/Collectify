# 插件安装与分发

Git 用于开发者管理源码。用户通过 Collectify 的插件管理安装程序，不需要克隆仓库、安装 Node.js 或运行 Git。

## 用户操作

打开左下角齿轮 → 插件。

- **安装插件包**：选择下载的 `.collectify-plugin` 文件，核对名称、版本、ID、来源和声明权限，确认安装。
- **已安装**：打开、启用、停用、导出自有页面插件程序、卸载。
- **发现插件**：填写发布者提供的 HTTPS `catalog.json` 地址并保存，点击刷新。可搜索插件、下载新插件、更新已安装插件。
- **开发者选项**：保留源码目录安装入口，普通用户不需要使用。
- **卸载**：默认保留数据；确认框可勾选“同时删除该插件的全部本机数据”。这个选项不删除用户关联的本地原文件。
- **恢复默认插件**：已卸载的默认插件列在已安装列表下方。恢复采用当前应用随包提供的版本；保留过的数据继续使用，明确删除过的数据不重新从旧库或示例灌入。

相同 ID 更新同一插件，不产生第二份数据。禁止降级，程序改变必须提高 `manifest.version`；相同版本的原样包可重复安装。更新保留启停状态和独立数据库。

在线目录在首次点击“发现插件”、刷新或安装时联网，打开通用设置不会自动下载。下载有 30 秒超时；失败在插件面板中显示原因，可以重试。刷新失败保留上次成功的目录。安装前展示权限，增加的权限会单独标明。

应用内置官方目录地址，空地址设置自动使用官方源；首次点击“发现插件”时读取目录，也可手动刷新。第三方目录仍可填写自己的 HTTPS 地址，并可点击“使用官方源”恢复。官方插件包通过同一 GitHub 仓库的 Releases 分发，目录生成、发布与更新流程见 [官方目录维护](../plugins/README.md)。离线安装也继续可用。

## 程序包与数据备份

`.collectify-plugin` 是普通 ZIP 容器，根目录直接包含 `manifest.json`、入口 HTML、脚本、样式与其他静态资源，不要在外面再套一层目录。

程序包中没有用户数据库、剪贴板历史、宿主设置或 MCP 令牌。分享插件时使用“导出插件包”，备份用户内容时使用“设置 → 导入 / 导出”。两种文件用途独立，数据文件不会执行或安装程序。

默认插件同样可停用、卸载、恢复。它们的原始资源处于只读应用包内，卸载使用宿主数据库中的持久记录屏蔽加载，应用升级不会清除这个记录。默认程序随 Collectify 安装包分发和更新，不提供单独程序包导出；不能将任意下载文件作为原生 Node.js 后台加载。第三方下载仅开放沙箱页面插件，AI 可以将现有默认页面插件克隆为新 ID 的自有插件再导出。

保留数据的默认插件卸载后，仍可在全局数据导出中选择其内容。随包的领域处理器只用于数据备份，不会激活插件页面、提醒、桌面组件或 MCP 业务工具。处理器无法读取数据时会明确报错，不会仅导出偏好并伪装成完整备份。

## 发布自有页面插件

在项目目录执行：

```powershell
node scripts/package-plugin.cjs D:\plugins\my-plugin D:\plugin-releases
```

将生成 `<插件ID>-<版本>.collectify-plugin`，同时输出 SHA-256。安装包只含源码目录中的静态产物。

生成在线目录：

```powershell
node scripts/package-plugin.cjs D:\plugins\my-plugin D:\plugin-releases https://example.com/releases/
```

`example.com` 仅为命令格式示例，请替换为实际发布地址。命令会同时生成或更新输出目录中的 `catalog.json`，同 ID 保留本次版本，其他插件条目保留。

将目录和它引用的安装包上传到所填 HTTPS 地址，再将 `catalog.json` 的真实地址提供给用户。脚本只生成文件，不上传、不创建 GitHub Release、不执行 commit 或 push。GitHub Releases 的插件包与目录作为 release assets 发布时，下载目录可填写对应 release 的 `/releases/download/<tag>/` 地址。

目录合同：

```json
{
  "format": "collectify-plugin-catalog",
  "version": 1,
  "plugins": [
    {
      "id": "example.hello",
      "name": "问候",
      "description": "独立页面插件",
      "version": "1.0.0",
      "apiVersion": 1,
      "size": 1234,
      "sha256": "替换为生成的64位小写SHA-256",
      "url": "https://example.com/releases/example.hello-1.0.0.collectify-plugin"
    }
  ]
}
```

示例中的大小与校验值需要使用实际产物信息。SHA-256 校验下载内容是否与目录一致，并不代表发布者身份签名；用户应选择可信的目录发布者。目录暂不提供账号登录、付费购买、签名信任链或原生后台的独立远程升级。

## 安装边界

- 安装包不超过 12 MB，展开后不超过 10 MB、300 个文件、500 个目录项、20 层目录。
- ZIP 支持 Store / Deflate，拒绝加密、分卷、ZIP64、符号链接、越界路径、重名、文件目录冲突和损坏内容。
- 在线包必须匹配目录提供的 ID、版本、大小和 SHA-256；拒绝 HTTPS 降级与无限重定向。
- 页面清单须使用当前支持的 API 与权限；不接受原生后台入口。
- 暂存校验后原子替换程序目录；一般安装异常会回滚旧程序，数据不参与程序覆盖。
- 安装确认发生在运行插件之前；程序安装后的实际功能仍应由开发者测试。

本机目录：`plugin-packages/<ID>/` 保存程序，`plugins/<ID>/data.sqlite` 保存数据，`plugin-staging/` 用于解包暂存。宿主 `host.sqlite` 保存启停、默认插件卸载记录与在线目录地址。插件草稿仍位于 `plugin-drafts/`。
