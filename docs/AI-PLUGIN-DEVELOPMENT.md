# 通过 AI 扩展 Collectify

目标是用户描述所需功能，AI 通过 MCP 编写插件并直接接入工作台，不需要用户手工修改项目、复制代码或重新打包宿主。

## 从连接到使用

1. 重启开发程序或安装包含该能力的版本。
2. 在“设置 → AI 连接”开启 MCP，复制连接配置，在支持 Streamable HTTP 的 AI 客户端接入。
3. 已连接过旧版本的客户端需要刷新工具列表或重新连接；具体入口取决于客户端。
4. 确认客户端能发现 `get_plugin_sdk`、`create_plugin_draft`、`write_plugin_files` 和 `install_plugin_draft`。
5. 直接向 AI 说明需求，例如：

```text
请通过 Collectify MCP 给我新增一个剪贴板文本历史插件。
需要搜索、去重、保存最近 30 条和一键复制。
请先读取真实 SDK 合同，再写入草稿、校验、安装启用并打开，
不要只把代码发给我，也不要修改 Collectify 的宿主源码。
```

安装成功后，它会与收藏、待办等插件出现在同一层导航中。以后修改该插件，也可以直接告诉 AI。用户仍可在“设置 → 插件”中停用或卸载它。

MCP 初始化会向 AI 提供插件开发说明，但最终是否正确调用工具仍取决于连接的 AI 客户端和模型。应用没有内置大模型。

## 开发工具

| 工具                        | 用途                                                     |
| --------------------------- | -------------------------------------------------------- |
| `get_plugin_sdk`            | 当前 API、权限、资源、模板、限制和推荐流程               |
| `list_plugins`              | 已安装程序版本、清单、权限、启停及导航，不含用户数据库   |
| `create_plugin_draft`       | 从模板或现有页面插件创建隔离草稿；更新默认递增 patch     |
| `get_plugin_draft`          | 草稿列表或指定草稿的 revision、清单、文件列表和安装回执  |
| `read_plugin_file`          | 分页读取草稿内的 UTF-8 静态程序文件                      |
| `write_plugin_files`        | 按 revision 原子写入／删除一批包内文本文件               |
| `validate_plugin_draft`     | 清单、资源和脚本静态校验，返回安装凭据                   |
| `install_plugin_draft`      | 安装同一 revision 的原样校验结果，可启用并打开           |
| `get_plugin_runtime_status` | 加载状态、错误类别及源文件位置；不返回页面文本或日志原文 |
| `set_plugin_enabled`        | 按用户要求启停插件，数据保留                             |
| `discard_plugin_draft`      | 删除不再需要的草稿，不卸载程序、不删除插件数据           |

AI 不需要获得项目源码目录或任意 shell。程序写入限定在用户数据目录的 `plugin-drafts/<draftId>/package/`，正式程序仍由插件安装器管理。

## 版本、校验和更新

- 创建草稿后得到 `draftId` 和 `revision`。写入需带 `expectedRevision`，成功后递增版本，过期写入被拒绝。
- 单批写入最多 64 KB UTF-8 文本，可多批修改；每批最多 20 个文件和 20 个删除路径。总包大小及文件数量沿用插件安装限制。
- 只接受包内相对路径，拒绝绝对路径、`..`、符号链接、保留设备名、隐藏依赖目录和原生后台入口。
- 静态校验在有时间及内存限制的工作线程中编译经典 JS，不执行生成的代码。内联脚本、事件属性、未知资源和不支持的模块脚本会报告问题。
- 安装必须携带同一 revision 的 `validationToken`。修改文件后旧凭据失效，不能把未完成的半批文件安装进去。
- 修改已安装程序要提高清单 `version`。新建更新草稿默认递增 patch；安装同 ID 后保留数据和启停状态。
- 草稿创建之后若正式程序被另一个草稿或本地安装更新，会拒绝覆盖，要求从最新版本重新创建。
- 安装响应不明时，先用 `get_plugin_draft` 和 `list_plugins` 核实结果，不要盲目重复创建插件。

默认插件不会被 AI 草稿覆盖。自有页面插件可以克隆和更新；默认的纯页面插件也可克隆为新的插件 ID。带原生后台的默认业务插件不作为页面草稿克隆。

## 剪贴板示例与权限

`clipboard-history` 是一个未默认安装的模板，不是宿主中的固定业务。AI 可以读取并改写它，再安装为用户自己的插件。

模板声明 `storage`、`clipboard.read`、`clipboard.write`。采集默认关闭，由用户点击“读取一次”或“开启采集”；最多保存 30 条、每条 2000 字符，存入该插件自己的 SQLite 键值数据。

当前 `clipboard.readText()` 仅在该插件页面显示、主窗口可见且未最小化时允许。切换插件、弹出宿主设置、隐藏窗口或停用插件时暂停交付，异步读取期间发生隐藏也不会再交付文本。它不是全系统后台剪贴板守护服务，重启程序也不会自动开启采集。

开发工具不提供读取系统剪贴板、历史数据库、收藏密码或任意本机文件的能力。运行诊断仅返回错误类别、文件与行号，不回传日志原文，避免把插件处理的文本交给 AI。普通业务工具仍按各插件自己的数据合同工作。

## 验证边界

`valid: true` 代表静态合同、资源和语法检查通过；`ready` 代表页面加载完成。两者都不等于插件业务行为已完整测试，AI 应依据用户需求核对结果，不把“安装成功”描述成所有功能已验证。

当前集成测试使用真实 MCP 客户端完成 SDK 发现、草稿修改、校验、安装、更新、导航、启停和越权拒绝。剪贴板功能注入了测试文本，避免读取或覆盖用户当前系统剪贴板。Windows 目录包还验证打包后的模板与编译线程；macOS／Linux 未实机验证。
