# 让 AI 操作Collectify

Collectify 5.4 自带本机 MCP 服务，可供群枢 / AIOA 等支持 Streamable HTTP 的客户端连接。本功能不内置大模型，整理和排期的理解能力由连接的 AI 工具提供。

## 在Collectify开启

1. 打开Collectify，点击侧栏底部“设置与 AI 连接”。
2. 在 AI / MCP 连接区域选择本机端口，默认 17863，点击“开启 MCP”。
3. 确认显示“已开启”和本机地址。如果端口被其他程序占用，会直接报错，换一个端口后重试。
4. 点击“复制 MCP 连接配置”。内容含 `url` 和 `Authorization: Bearer ...` 请求头；令牌只在本机生成，不需要从外部申请。

服务默认关闭。主动开启后会记录开启状态，之后启动自动恢复。关闭窗口并保持托盘驻留时仍可使用；完全退出Collectify则服务停止。

## 在群枢 / AIOA 连接

在群枢的 MCP 管理界面新增服务器，选择 Streamable HTTP，名称可填 `collectify`。将复制配置中的 `url` 填到服务器地址，将 `headers.Authorization` 作为同名请求头填入。保存并启用，然后使用该客户端的连接测试功能。

本轮仅实现了Collectify服务端，没有代改群枢配置或自动注册服务。群枢不同版本的按钮名可能略有差异；此处没有声称核验过你当前版本的管理界面。若在群枢对话中明确要求添加这个服务，应由群枢的 MCP 添加确认卡完成。

通用配置结构（令牌以复制出的本机值为准）：

```json
{
  "mcpServers": {
    "collectify": {
      "type": "streamable_http",
      "url": "http://127.0.0.1:17863/mcp",
      "headers": { "Authorization": "Bearer <本机生成的令牌>" }
    }
  }
}
```

不要把这份配置公开分享。连接只接受本机回环，不监听局域网；浏览器 Origin 请求被拒绝。不能拿此地址从另一台电脑直连。

## 可调用能力

| 工具 | 用途 |
|---|---|
| workspace_summary | 读取分类、收藏、待办数量、本机时间和时区 |
| list_bookmarks | 按关键词、分类查询资源，不返回用户名或密码 |
| list_tasks | 按日期、状态、关键词、归档状态查询待办与日程 |
| save_tasks | 一次创建或更新最多 100 个待办，设置计划区间、截止、提醒、重要性等 |
| save_note | 新建或更新便签 |
| organize_bookmarks | 将一批现有收藏移动到分类，分类不存在时新建 |

例子：“先查我明天的任务，把需要专注的两件事安排到上午 10 点和下午 3 点，每件一小时，开始前 10 分钟提醒。”“把 Jenkins 相关收藏整理到构建工具分类。”“把这段发布步骤保存成便签。”

`save_tasks` 先完整校验再一次写入；一项无效则整批不落盘。更新传已有 id，未传 id 则新建。时间使用含时区的 ISO 字符串。AI 调用写操作会直接保存并同步到界面，不再逐次弹确认；请在 AI 端说清要求。工具不提供删除、执行本地文件、发送消息、读取密码的能力。

数据使用应用内同一份 Store，由 SQLite 事务提交。成功写入与 `mcp_audit` 表中的审计记录属于同一事务，只记录工具名、时间和结果，不记录令牌、密码或任务正文。连接信息位于同一个数据库的 `mcp_connection` 表，不再单独保存 JSON 文件。

## 验证范围

使用官方 MCP SDK 的真实客户端测试了初始化、工具发现、鉴权、密码字段隔离、批量校验失败不写入、创建 / 更新任务、整理分类、持久化与停用。另通过打包应用的设置弹窗验证开启状态。尚未代你在群枢实际添加连接。
