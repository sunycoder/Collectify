# 默认安装插件独立分发

从 5.7.18 起，收藏、待办、便签、时间戳和 JSON 工具均为标准可更新插件。默认安装只是安装策略，不再禁止单个插件更新或导出。

## 用户行为

- 首次启动从安装包中的五个初始插件包安装至用户 `plugin-packages` 目录，默认启用；无需联网下载才能开始使用。
- 插件市场统一提供发现、安装和更新，程序与用户数据分目录存放，更新不改变原数据、排序或启停状态。
- 主程序重启或升级不覆盖已经存在的插件程序，不自动补装用户卸载的默认插件。
- 旧版本的停用、卸载及导航顺序记录继续保留，原插件 ID 与数据库目录不变。
- 卸载并保留数据时，将原程序保留在隐藏恢复目录，供离线恢复和领域数据备份使用，不激活页面、提醒或 MCP。彻底删除同时清除恢复副本，并记录空数据初始化，避免导回旧示例。
- 在线市场安装使用在线版本；“恢复默认插件”作为离线恢复入口，优先恢复保留程序，首次没有副本时使用初始包。

## 开发与发版

业务源码仍按 `src/plugins/<name>` 维护，构建产物在 `src/default-packages/collectify.<name>`。原生插件后台将自身模型、存储、校验和业务打入 `backend.cjs`；辅助窗口与前端资源放入本插件包。宿主只提供 `backend-sdk` 公共接口。

修改插件后提高它的版本，执行 `npm run defaults:build`，使用本机发布者私钥签名；再执行 `npm run plugins:build`。目录现在包含 11 个可下载插件，五个默认安装插件与其他插件使用相同的发布脚本、包校验和市场安装链路。

CI 使用 `defaults:check` 检查提交产物与源码一致，不持有私钥，也不在流水线生成签名。主程序构建不重打插件包，以免无关宿主变更悄悄改变同版本插件。

主程序安装包排除 `src/plugins` 开发源码，只带五个初始插件包和公共宿主能力。后续普通插件业务修改可以只发布对应插件；新增公共 SDK 能力时仍需要提高最低宿主版本并更新主程序。

发布验证结果见 5.7.18 的 CI 和发布流水线；本地 Windows 验证不能替代跨平台结果。
